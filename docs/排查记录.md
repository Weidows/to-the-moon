# 排查记录

## 播放卡顿（2026-10-31）

反馈是「视频里有多次卡顿」。片源侧逐项测过，结论是**片源没问题**：

| 检查 | 方法 | 结果 |
| --- | --- | --- |
| 帧间差 | 每 0.03 s 抽帧算灰阶平均绝对差（40/99/118/160/262 s 五段） | 0.13–1.15，无突跳、无静止帧 |
| 完整解码 | `ffmpeg -v error -i out/*.mp4 -f null -` | 0 行错误 |
| 章节接缝 | 9 个交界各抽 ±0.2 s 三帧量亮度 | 最低 11.6（钢琴房、灯塔夜景），均有内容不是空帧 |
| 音轨 | `volumedetect` | mean −18.8 dB / max −1.0 dB |

当时的背景是本地 ComfyUI 开着占 GPU，播放器抢不到资源。判断方法：用 `-c copy`
切一段（码流与成片完全一致）和一个重压过的版本对比播放——

- copy 卡、重压不卡 → 码率/解码问题
- 两个都卡 → 播放器或显卡
- 两个都不卡 → 当时就是 GPU 被占

## 近黑镜头（2026-10-31）

按 `Shot` 的中点逐镜抽帧量亮度（`top60%` 均值），29 个镜头里只有 `starfield_cliff.jpg`
掉到 **4.8**，其余最低 15.2。它在 04 初见 308–700、05 约定 398–730 各用一次，
合计约 24 秒几乎全黑，观众只能看见字幕。

原因：原图 mean 只有 18.5，再叠 `FilmOverlay` 的 tint（multiply）＋ vignette（0.72）
＋ `Scrim`，暗部被压到 1/4。

**不要用 gamma 硬提**：试过，会把 JPEG 块噪和 8 位量化台阶一起放大——抽帧可见星空块噪、
蓝色星云出色带，成片从 163 MB 涨到 206 MB。

正解是重画一张本来就亮的图（MOSS，mean 47.5），再配 `brightness={1.2}`，落地后
30.1 / 31.0，和同场邻居（`kids_plane` 34.8、`gen_carnival` 34.6）同一量级。

以后加新镜头就跑一遍这个体检：按中点抽帧、算 `top60%` 均值，低于 12 就是要处理的对象。

## 底部黑边（2026-11-04）

`Scrim` 原来从画面 64–70% 高度往下铺，梯度在自身 60% 处就到 91% 不透明度、88% 处全黑，
下半屏三分之一实际是实心黑条。

- 高度改为 54–60%，梯度改成 0 → 0.30 → 0.59 → 0.87 匀速爬升
- 字幕改用 `theme.HALO` 字形光晕（`TextBlock` + `Quote`），亮背景下照样读得清
- 实测画面下 1/3 平均亮度：34 s 6.4 → 22.3、124 s 9.4 → 27.6、264 s 5.1 → 14.2
